This page documents every zick subcommand, its arguments, defaults, and the result it returns. Output is an NRDL document by default; use --set-output-format json to get JSON instead.

How Options Are Gathered

zick is a CLIFF-powered program. Every option can be given through three channels, in order of precedence — configuration files, environment variables, then the command line — with later values overriding earlier ones.

Configuration files live in three places, each overriding the one before it:

  • A system-wide file: /etc/zick/config.nrdl on Linux/POSIX, /Library/Preferences/zick/config.nrdl on macOS, and %PROGRAMDATA%\zick\config.nrdl on Windows
  • A per-user file: ${XDG_CONFIG_HOME}/zick/config.nrdl(by default ~/.config/zick/config.nrdl) on Linux/POSIX, ~/Library/Preferences/zick/config.nrdl on macOS, and %LOCALAPPDATA%\zick\config.nrdl on Windows
  • A project file named .zick.nrdl in the directory zick is run from, or any of its parents

Every option also has an environment variable, named ZICK_<KIND>_<OPTION>:

  • ZICK_FLAG_<OPTION>=1 enables a flag
  • ZICK_ITEM_<OPTION>=<VALUE> sets a string value
  • ZICK_LIST_<OPTION>=<V1>,<V2>,... sets a list option
  • ZICK_TABLE_<OPTION>=<K1>,<V1>=<K2>,<V2>=... sets a key/value table option
  • ZICK_NRDL_<OPTION>=<NRDL_STRING> sets a value using an NRDL string
  • ZICK_FILE_<OPTION>=<FILE_PATH> sets a value from the contents of an NRDL document in a file, as if by the --file-* flag
  • ZICK_RAW_<OPTION>=<FILE_PATH> sets a value from the raw bytes of a file, as if by the --raw-* flag

On the command line, options take a spelling that matches their kind: --enable-<option> and --disable-<option> for flags, --set-<option> <value> for strings, --add-<option> <value> for lists, --reset-<option> to restore a default, and the --nrdl-*, --file-*, and --raw-* spellings for structured values. Short aliases are listed per subcommand below.

Common Options

Two options apply to every subcommand:

  • -d/--set-start-directory — the directory to start the zick search from. Defaults to the current working directory. zick walks up from here looking for the .zick-db marking directory that names the project's database.
  • --set-output-format — "nrdl"(the default) or "json". Controls the format of the emitted result document.

The defaults for the remaining options are shown on the zick help page under "The following options have been detected": cascade false, download-package true, dry-run false, output-format "nrdl".

init

Initializes the zick database in the start directory: it creates the .zick-db marking directory and the store file (packages.nrdl inside it). Commands run without init create the store on demand the first time they open it.

  • Arguments: none beyond the common options
  • Aliases: none

Result:

{
    result successful
    status successful
}

add

Downloads the zip archive at a URL, unpacks it into the project tree, and records the package and the files it owns in the store.

  • -k/--set-package-name — the package name. Required.
  • -V/--set-package-version — the package version. Required.
  • -l/--set-package-location — the URL of the zip archive. Required.
  • -u/--add-package-dependency — a dependency on another installed package, by name. May be given more than once. The dependee must already be installed.
  • -m/--set-package-metadata — a JSON string of extra metadata, honored for its zick key: config-files(paths to treat as configuration files) and ghost-files(paths to record without writing).
  • --json-download-authorizations — a JSON string mapping hosts to authorization records (type of "basic", "header", or "oauth-token"), used when downloading the archive.
  • -W/--disable-download-package and -w/--enable-download-package — whether to download and unpack the archive. Downloading is on by default; -W records the package from its options alone, without touching the network or the tree.
  • -n/--enable-insecure and -N/--disable-insecure — disable TLS certificate verification when downloading.
  • -g/--enable-allow-downgrades and -G/--disable-allow-downgrades — allow re-adding a package at a lower version than the one installed. Off by default.
  • -i/--enable-allow-inplace and -I/--disable-allow-inplace — allow replacing the currently installed version with one that compares equal. Off by default.

Result (on success):

{
    result successful
    status successful
}

zick signals an error when a dependency named by -u is not installed, or when a file in the archive is already owned by another package.

files

Lists the files owned by an installed package.

  • -k/--set-package-name — the package name. Required.

Result when the package is installed:

{
    package-files [
        {
            checksum "9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822c"
            class normal-file
            path "bin/tool"
            size 42
        }
    ]
    result package-found
    status successful
}

When the package is not installed, the result is result not-found and package-files is omitted. File classes are normal-file, config-file, and ghost-file.

info

Shows information about an installed package: its name, version, location, and metadata.

  • -k/--set-package-name — the package name. Required.

Result when the package is installed:

{
    package-information {
        location "https://example.com/mylib-1.2.0.zip"
        metadata {
        }
        name "mylib"
        version "1.2.0"
    }
    result package-found
    status successful
}

When the package is not installed, the result is result not-found.

dependers

Lists the installed packages that depend on the named package.

  • -k/--set-package-name — the package name. Required.

Result when the package is installed:

{
    package-dependers [
        {
            location "https://example.com/myapp.zip"
            name "myapp"
            version "0.1.0"
        }
    ]
    result package-found
    status successful
}

When the package is not installed, the result is result not-found. An empty list of dependers renders as package-dependers [ ].

dependees

Lists the packages the named package depends on.

  • -k/--set-package-name — the package name. Required.

The result shape mirrors dependers, with the key package-dependees instead of package-dependers.

remove

Uninstalls a package: deletes the files it owns (backing up its configuration files) and removes its record from the store.

  • -k/--set-package-name — the package name. Required.
  • -c/--enable-cascade and -C/--disable-cascade — with -c, also remove the packages that depend on the named one, sinks first. Off by default; without it, removing a package that others depend on signals an error.
  • -r/--enable-dry-run and -R/--disable-dry-run — with -r, compute and report the removal without touching the tree or the store.

Result when the package is installed:

{
    dry-run false
    removed-packages [
        {
            location "https://example.com/myapp.zip"
            name "myapp"
            version "0.1.0"
        }
    ]
    result package-found
    status successful
}

With -c, removed-packages lists every removed package, sinks first. When the package is not installed, the result is result not-found.

list

Lists the installed packages, sorted by name.

No arguments beyond the common options.

Result:

{
    packages [
        {
            location "https://example.com/mylib-1.2.0.zip"
            metadata {
            }
            name "mylib"
            version "1.2.0"
        }
    ]
    result successful
    status successful
}

When nothing is installed, zick prints nothing and exits 0.

orphans

Lists the orphaned packages: the installed packages that nothing depends on (the source nodes of the dependency graph).

No arguments beyond the common options.

Result:

{
    orphaned-packages [
    ]
    result successful
    status successful
}

An empty store renders orphaned-packages [ ] — never false — because the collection is emitted as an empty sequence.

verify

Checks the files of an installed package against the store: size and SHA-256 checksum for normal-file records, presence for config-file records. Ghost files are expected to be absent.

  • -k/--set-package-name — the package name. Required.

Result when every file checks out:

{
    result package-found
    status successful
    verification-results [ ]
}

When verification finds problems, zick exits 4 and reports each problem class under verification-results:

{
    result package-found
    status verification-failed
    verification-results {
        checksum-discrepancy [
            {
                path "bin/tool"
                source-checksum "9f86d081884c7d659a2feaa0c55ad015a"
                target-checksum "a3bf4f1b2b0b822c2ad5023b9c5b7f8d1a"
            }
        ]
        file-missing [
            {
                path "lib/mylib.lisp"
            }
        ]
    }
}

The possible result keys are file-missing, size-discrepancy, checksum-discrepancy, config-file-missing, path-not-file, and path-not-directory.

When the package is not installed, zick exits 3 with status package-not-found.

help

zick help(or -h/--help) prints the CLIFF help page: how options are gathered, the alias table, the detected defaults, and the list of subcommands. zick with no subcommand prints a short usage summary instead.

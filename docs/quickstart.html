This is a five-minute tour: initialize a project, install a package, look at what you got, verify it, and remove it. Every command here works against a real zick build — run them in a scratch directory to follow along.

Set Up a Project

Make a directory and initialize it:

mkdir my-project
cd my-project
zick init

zick init creates the .zick-db marking directory and the store. zick finds the project by walking up from wherever you run it, looking for that directory — so from now on, running zick anywhere inside my-project — or below it — talks to this project.

Install a Package

A package is a zip archive at a URL. Install one with zick add, naming it with -k, versioning it with -V, and locating it with -l:

zick add -k mylib -V 1.2.0 -l https://example.com/mylib-1.2.0.zip

zick downloads the archive into a staging area, unpacks it into the project tree, and records the package and every file it owns — path, size, and SHA-256 checksum — in the store. Success looks like:

{
    result successful
    status successful
}

Declare that one package depends on another with -u: the dependee must already be installed.

zick add -k myapp -V 0.1.0 -l https://example.com/myapp.zip -u mylib

-W skips the download and records the package without unpacking its files — useful for metadata-only records, or for following along offline. (The archive URLs in this tour are examples; substitute real archives you can download.)

Look at What You Got

See what is installed:

zick list

{
    packages [
        {
            location "https://example.com/mylib-1.2.0.zip"
            metadata [
            ]
            name "mylib"
            version "1.2.0"
        }
        {
            location "https://example.com/myapp.zip"
            metadata [
            ]
            name "myapp"
            version "0.1.0"
        }
    ]
    result successful
    status successful
}

See the files a package owns:

zick files -k mylib

{
    package-files [
        {
            checksum "f5804ac61aa4b37500ea52077f984d7224a35d3e2d05644d62ac4940384cfa6e"
            class normal-file
            path "mylib/bin/tool"
            size 44
        }
    ]
    result package-found
    status successful
}

Ask who depends on whom:

zick dependers -k mylib
zick dependees -k myapp

Verify

Check that the files on disk still match what was installed:

zick verify -k myapp

{
    result package-found
    status successful
    verification-results [
    ]
}

zick exits 0 when everything checks out, 3 when the package is not installed, and 4 when verification finds problems (with the failing files listed under verification-results). Try deleting one of the installed files and re-running verify to see the report — that is what a git clean or a bad deploy looks like to zick.

Remove

Uninstall a package with zick remove. Its files are deleted (its configuration files are backed up first) and its record leaves the store:

zick remove -k myapp

Removing a package that others depend on is an error unless you pass -c to cascade, removing the dependents too. Preview a removal without touching anything with -r:

zick remove -k mylib -c -r

And when you want to find the cruft — packages nothing else depends on — ask zick:

zick orphans

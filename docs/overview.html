zick is a package manager for project-level source-code repositories: it installs zip archives into a project tree, tracks which files each package owns, and verifies the result on disk. The name is a backronym — **Zip files In Concert** — and the idea is to be the "RPM" or "DEB" for a project rather than for a whole machine.

The mental model is small:

  • A project is marked by a .zick-db directory, found by walking up from where you run zick. Everything zick knows about a project lives under that directory.
  • Packages are plain zip archives served over HTTP(S). zick add downloads one, unpacks it into the project tree, and records the result.
  • The store — an NRDL document of installed packages and the files they own, with sizes and SHA-256 checksums — lives in the .zick-db directory. It is the source of truth for what is installed.
  • zick verify checks the files on disk against the store, so a git clean, a bad deploy, or a partial restore can't silently break your environment.

zick is built for two audiences:

  • Dev machines, where you set up the dependencies you need to do programming work — a toolchain bundle, a set of prebuilt libraries, a data pack.
  • CI/CD, where a checkout plus zick add plus zick verify is a reproducible, auditable install step.

How zick Fits with the Resolver

zick pairs well with dsolv, a generic dependency resolver. They are independent tools built to be used together:

  • dsolv reads a repository of cards describing versions and requirements, and tells you the exact set of versions a build needs — returning the URLs of the files to download.
  • zick takes those URLs, downloads the archives, unpacks them into the project tree, tracks the files it owns, and verifies them.

dsolv answers "what do we need?"; zick answers "make it so, and check." This manual covers zick on its own; the pairing is shown in the longer example and the architecture pages.

What zick Does Not Do

zick is deliberately small:

  • It does not resolve versions. You give zick add a name, a version, and a URL; zick installs exactly that. Version selection is the resolver's job, not zick's.
  • It does not build or compile anything. Archives are unpacked as they are; publishing is just uploading a zip.
  • It does not manage your whole machine. zick installs into one project tree, and its ownership database lives in that project.
